## 方針（2026-11-06 オーナー）
- **3DCG を優先して投稿する。** 長尺の投稿キュー（scripts/sns/yt_long.py の ORDER）に 3DCG（cg-*）が残っていれば、通常の長尺より先に出す（yt_long.py next が cg-* を先に選ぶ）。道具紹介（HOLD）は除く。
- 共通ルール：既存の動画と重ねない。釣り場ガイド・海上釣り堀・道具紹介（オーナー指示のものを除く）はやらない。最初の10秒で答えが知りたくなる問い。20〜40秒ごとに画面を切り替える。章の最後に小さなまとめ。最後にコメントで答えられる質問。事実だけを言い、言い切れないことは「〜と言われます」。立入禁止の場所は映さない・勧めない。
- 制作：three.js の3DCG＋VOICEVOX のナレーション。
- **冒頭とサムネイルは Blender（2026-11-12 オーナー：「リアルでわかりやすい、サムネイルも映える」。3DCG はすべてこの共通ルール）**：
  - 冒頭の章（オープニング）の映像とサムネイルの絵は Blender（Cycles）で作る。解説の部分（グラフ・ラベル・図）は今までどおり three.js。ナレーションの音声はそのまま。
  - 作り方：content/cg/<slug>.json に `blender_open`（scene・title（2行）・sub）を足す → cg-video で書き出し → **cg-blender-open.yml**（slug・video_run＝その cg-video の実行 ID）を mode=test で回して確かめる → mode=full で、long-media の投稿用の動画（<slug>.mp4.part-*）とサムネイル（<slug>.jpg）を差しかえる → cg-compress は使わない（full が差しかえる）。
  - 場面は scripts/cg/blender/scenes/<scene>.py（今ある：tairaba＝タイラバとマダイ、jig＝メタルジグとブリと群れ）。動きは時刻 t だけで決まる式で書き、魚は Fish Kit。新しい釣り方は場面を足す（似た場面は使い回してよいが、魚と仕掛けはその回のものにする）。
  - 長さは冒頭の章より少し長く（例：12秒の章なら13秒）。食う瞬間は章の終わり近くに置き、題の文字は後半で消える（apply_opening.py）。
  - 時間の目安：1280×720・64サンプルで1コマ約3〜4分（GitHub の4コア）。15台に分けて、12秒（24fps）で約1時間半。サムネイルは1枚約10分。
  - 魚が海底より下に行かないことを毎コマ記録している（timing の3列目。summary に最小値）。0.2m 以上あること。
- **エンディングの魚は Fish Kit（2026-11-12 オーナー：「そこだけ劣化して見える」。今後の動画共通）**：main.js の end・short_end は endFish（ブリの群れ・アジ・マダイ、明るい中層）になった。新しい動画で end を作り直さない。
- **仕掛けの通った道（軌道）は要所だけ（2026-11-12 オーナー）**：しゃくりがあると糸と見分けにくく、画面がごちゃつく。軌道は「動きを比べる・説明する」場面だけに出し、ftRig の trailDots: true（水色の点）で描く。凡例に「ジグが通った道（点）」を出す。ほかの場面は trail を付けない。
- **ジグは実物の比率**：makeJigReal（17cm・細身で平たい、銀の腹とホログラム、色の背、目、アシストフック）。makeJigModel（丸く太い）は使わない。
- **アイキャッチ（2026-11-12 検討の結論）**：2〜4分の動画には入れない（中身のない数秒は離脱のきっかけになりやすく、章の区切りは章番号・字幕・目次で足りている）。5分を超える動画を作るときだけ、真ん中に1回（3秒以内、Blender の絵＋次の問い）を試す。

#### 船釣り 見える化シリーズ（共通の作り）
- 絵：船（port の boat を流用・改良）と海の断面。船から下りる糸・仕掛け・オモリ／ルアーの動き、魚のいるタナ、潮の流れ（光る粒）を1画面に1つずつ見せる。
- 毎回の型：①最初の1秒で「船の下で何が起きている？」の絵と問い ②魚探の画面（左上の全体図の代わり。深さとタナを示す）③誘い・巻き方の動きをスローで ④クイズ「どのタナで食う？」「どう合わせる？」の答え合わせ ⑤安全（ライフジャケット。船長の指示を聞く）⑥まとめ。
- 色（シリーズで固定）：水色＝潮の流れ、オレンジ＝仕掛け・ルアーの通り道、緑＝食うタナ・正解、赤＝危険。凡例は右上。
- 事実：旬の時期・水深・オモリやジグの重さは、遊漁船の案内・釣具メーカー・公的機関の資料で確かめ、「例えば」「〜と言われます」と付ける（地域・日で変わる）。魚の動き・アタリの瞬間は「イメージ」と明記。特定の遊漁船・店の名前や評価は出さない。製品名は出さない（道具紹介にしない）。
- タイトルは「船の〇〇、海の中はこうなっている」型（問いを先に）。サムネは船と光る糸を主役に。
- 共通の部品（main.js の ft_*。第1回 cg-fune-tachiuo で作成）：海の断面（1=1m、海底 y=-70）、遊漁船（ftBoat）、全体図（ftMini）、竿とリールの表示（ftCtl）、高さのグラフ（ftGraph）、仕掛けを追うカメラ（ftCam）。
- **仕掛けの動きは計算する**（2026-11-11 オーナー：「ジグ・テンヤの動きを忠実に演算すると参考になる」）：ftSim（重さ・浮力・水の抵抗・糸の張りの2次元モデル）に、操作の列（FT_SEQ：巻く・止める・しゃくる・クラッチを切る）を入れて動きを出す。係数は形と重さから決めた目安で実測ではないので、画面に「簡単な物理モデルの計算」と出し、計算で出た数値（沈む速さなど）は言わない。新しい仕掛けは FT_BODY に足す。
- **魚は写真から作った3Dモデルを使う**（2026-11-12 オーナー）：Fish Kit（CC0 1.0、https://cda-social.github.io/fish/gallery.html）を scripts/cg/vendor/fishkit に取り込み済み。main.js の fkGet(id, i, cm)・fkPlace(f, 位置, 向き, 頭の上げ角, T)。使える魚：aji, seabass, mebaru, kasago, saba, tachiuo, sawara, kamasu, buri, hiramasa, kihada, magochi, kurodai, madai, katakuchi, isaki, onagagure, kuchibuto, shibudai（読み込む種類は FK の loadFish の配列に足す）。動きは時刻 T から決める（分割して書き出しても飛ばない）。
- **イカは写真から作った Squid Kit を使う**（2026-11-12 オーナー）：Squid Kit（CC0 1.0、https://cda-social.github.io/fish/gallery#squid）を scripts/cg/vendor/squidkit に取り込み済み。アオリイカ（aori、胴30cm）とコウイカ（kouika、胴18cm）、エギ付き。glb ではなく、`loadSquids("vendor/squidkit/")`・`createSquid(id, { home, floorY })` で形を作り、`squid.update(dt)` で毎コマ頂点を動かす。動きは `setMotion`：hover・forward・backward・turn・escape（白くなって墨を吐いて逃げる）・follow（エギについて来る）・refuse（寄って離れる）・attack（触腕でエギを抱く）・hooked・surface・lifted・landed・rest・bury（コウイカだけ）。大きさは実寸（m）なので、海の断面（1=1m）に合わせて置く。`squid.object` を動かしたり拡大したりせず、home で置く。
  - **分割書き出しで飛ばないようにする**：キットの中で Math.random を使い（29か所）、動きは update の積み重ねで決まる。動画では、各コマで「t=0 から固定の dt（1/60）で update を積み直す」か、作ってから T まで進める関数を用意し、そのあいだ Math.random を種つきの乱数（main.js の rng(seed)）に差しかえる。8分割で書き出した前後のコマがつながるか、境目の2コマを並べて確かめる。
  - アオリイカの回（アカデミー・エギングの見える化など）はこれを使う。イカの動きは画面に「イメージ」と出す。
- **魚を砂や根に埋めない**（2026-11-11 オーナー）：魚は ftHeroAt・ftSchoolPlace で置き、下端が海底より上になるようにしてある。書き出す前に、全コマで下端と海底のすきまを確かめる（今回は最小 0.5m）。根や岩を置く回は、魚の位置と重ならないことを同じように確かめる。
